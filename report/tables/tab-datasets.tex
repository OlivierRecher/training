\figtext{%
The seven data regimes used over the internship, and the persistence baseline
each one produces. Event counts and record ranges are measured on the files
themselves; the first two rows are samples of the same day-file, so they share
its mean of about sixty-two records per user. Baselines are the values reported
for the corresponding runs.
\emph{The baseline is a property of the data, not of the model}: it moves
whenever the test users move, which happened each time a new approach required
data the previous files did not carry.}

\vspace{4pt}
\begin{minipage}{\textwidth}\footnotesize
\textbf{Events.} \sraw: $\approx$31{,}000 records over the 500 users.
\srawbig: 54{,}173 scored predictions.
\smob: 34{,}408 training and 8{,}725 test events.
\slev: 80{,}000 and 20{,}000, exactly $2.33\times$ more, all of it copies.
\stwok: 69{,}379 (900 users) or 146{,}713 (1{,}900 users) training events,
7{,}845 test events giving 7{,}745 predictions.
\seleven: 369{,}451 events at the 5{,}000-user tier rising to 1{,}538{,}379 at
21{,}000, and 14{,}705 test predictions.\\[2pt]
\textbf{Two baselines for \smob.} 45.5\,\% is measured on the last 20\,\% of
each test sequence; 43.1\,\% is measured on the whole sequence, position by
position, after the evaluation was widened in the sixth iteration. Every
\smob{} result is compared with the one that matches its own protocol.\\[2pt]
\textbf{Train and test users are disjoint} inside every regime, so nothing the
model is graded on was ever trained on. Each regime also draws its test users
afresh, which is why absolute scores from two regimes are not comparable and
only the gap to each one's own baseline is.
