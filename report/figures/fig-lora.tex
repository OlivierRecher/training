\caption{What LoRA and QLoRA do}
\label{fig:lora}
\figtext{%
\figpara{Three ways to adapt a model, at the same scale.}{The grey square is the
model, a stack of very large tables of numbers. In (a) every number is modified,
which has the highest ceiling in principle but requires holding each number in
memory together with about three more used to track how to adjust it, several
times the size of the model, and it does not fit on a free card. LoRA (b)
\cite{hu2022lora} freezes the big table and trains two narrow ones added beside
it, so about 2 numbers in every 100 ever move. QLoRA (c)
\cite{dettmers2023qlora}, used throughout this report, does the same and stores
the frozen table with four bits per number instead of sixteen, which quarters the
memory it occupies; that is safe precisely because those numbers are read and
never updated. What this decides is not accuracy but waiting time: with (c) one
run fits in half an hour on a free graphics card, so nine weeks buy thirty
experiments instead of two.}}
