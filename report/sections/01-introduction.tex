\section{Host Laboratory and Dataset Description}

This report documents a second-year engineering research internship conducted from
29 June to 28 August 2026 at the \host{}, under the supervision of \supervisor{}.
The laboratory holds a large dataset of anonymized mobile network records provided by a Czech mobile
telecommunications operator, which serves as the primary dataset for several research projects conducted by the laboratory's interns.

These records contain no personally identifiable information, such as user names or phone numbers, nor message content.
Each record line specifies an anonymized user identifier, the temporal timestamp, and the sequence of cells to which the mobile terminal was attached over a 24-hour period. This anonymized corpus constitutes the empirical foundation of the work described in this report.

\section{Research Objectives and Next-Cell Prediction Task}

Mobile terminals continuously attach to the cell offering the highest signal quality. As users move, the terminal hands over its connection from one cell to the next. The mobile operator logs an event line upon each cell transition, as well as periodically during stationary periods.

The central research objective of this internship is formulated as follows: \emph{given the initial segment of a user's daily mobility trajectory, can the model accurately predict the next cell to which the device will connect?} Predicting cellular transitions enables mobile network operators to optimize resource allocation, anticipate local capacity demands, and reduce connection drop rates through proactive handover initialization.

A fundamental distinction must be established between physical infrastructure and logical coverage areas.\footnote{\textbf{Base station}: a physical infrastructure site. \textbf{Cell}: the spatial coverage area served by one sector of a base station, in one radio generation.} A base station corresponds to a physical installation serving several directions and several radio generations. Each direction, in each generation, defines a distinct cell. The geographical study area evaluated in this work comprises 369 cells distributed across 113 base stations, representing an average of three to four cells per physical site. The target of the predictive task is the specific cell rather than the base station, which presents a higher predictive complexity than coarse-grained spatial localization.

\section{Next-Cell Prediction via Fine-Tuned Language Models}

\input{figures/fig-overview}

As illustrated in \textbf{Figure~\ref{fig:overview}}, the overall experimental architecture transforms continuous 24-hour attachment records into discrete token sequences, fine-tunes a language model on thousands of these daily user traces, and lets the model output a ranked list of candidate cells out of 369 possibilities. The dashed benchmark box at the bottom of the figure is the persistence baseline, a deterministic competitor requiring no training that already predicts correctly roughly seven times out of ten; every performance metric in this report evaluates progress relative to it.

At the core of this architecture is a \textbf{language model}.\footnote{\textbf{Language model}: a probabilistic model trained to estimate the probability distribution over sequences of discrete tokens. The underlying mechanics operate on arbitrary discrete sequences, allowing its application to spatial mobility traces.} While language models are conventionally employed for natural language processing, their mathematical framework operates on generic ordered sequences of discrete tokens. In this context, daily mobility traces are framed as ordered sequences of cell identifiers selected from a fixed vocabulary of 369 discrete cells.

Rather than using off-the-shelf general language models directly, parameter-efficient \textbf{fine-tuning} (PEFT) is applied. The internal parameters of the neural network are adapted using local mobility traces, specializing the model from a general natural language generator into a dedicated next-cell predictor for the target geographical region, as detailed in Chapter~\ref{ch:tools}. Alternative approaches explored in parallel research rely on prompting off-the-shelf models without parameter updates, addressing a distinct research scope.

\section{Baseline Evaluation: The Persistence Baseline}

To rigorously assess model performance, predictions must be evaluated against a strong deterministic benchmark: the \textbf{persistence baseline}.

The persistence baseline evaluates the heuristic rule: \emph{``the next cell is identical to the current cell''}. Despite its simplicity, this single-line baseline achieves an accuracy of \textbf{69.2\%} on raw daily network records, primarily because individuals remain stationary for large portions of the day. Beating it constitutes the key criterion for demonstrating true predictive capability, and across early experimental iterations it proved difficult to surpass.

\input{figures/fig-worked-example}

\textbf{Figure~\ref{fig:worked-example}} illustrates the mechanics of the persistence baseline compared to model predictions on two moments of the same user's day, one per row, where the letters A and B stand for two cells. The model receives a historical trajectory prefix in which each moment is an hour and a cell (left); at the evaluated moment, the hour is provided while the true target cell is hidden (middle), and the predictions of the model and of the persistence rule are graded against ground truth (right). In the first row, the user remains stationary, so repeating the previous cell yields a correct prediction for both the baseline and the model without requiring predictive intelligence. In the second row, the user moves to a new cell and the persistence baseline necessarily fails. Transition events are therefore the only evaluation moments where a model can demonstrate genuine predictive gains over the baseline.

Throughout this report, performance gains are reported as the \emph{difference in accuracy} relative to the persistence baseline. A reported gain of $+4.3\%$ indicates that the fine-tuned model achieves an accuracy of 54.5\% on a benchmark where the persistence baseline yields 50.2\% across identical evaluation instances. Evaluating relative performance delta ensures consistent comparisons across dataset revisions and experimental cohorts.

\section{Report Structure}

This report is organized by thematic research questions rather than chronological execution; the complete timeline of experimental iterations is provided in Appendix~\ref{app:timeline}. Each chapter from Chapter~\ref{ch:data} onward ends with a conclusion section summarizing what it established.

\begin{itemize}
  \item \textbf{Chapter~\ref{ch:sota}, State of the Art}, presents the published work this study builds on: the theoretical ceilings on how predictable human movement is, the usual way of building and scoring a next-location predictor, and the studies that justify grouping users by behaviour.
  \item \textbf{Chapter~\ref{ch:data}, Dataset Analysis and Preprocessing}, describes the operator's records line by line, shows that a record is not a movement and that one base station carries several cells, and explains how the raw day files were turned into the six sets of users used in the experiments.
  \item \textbf{Chapter~\ref{ch:tools}, Model Architecture and Evaluation Methodology}, presents the language model, the way it is adapted to the records at low memory cost, the way a day is written for it, and the procedure that scores each prediction against the persistence baseline. It closes on three measurement principles that every later result obeys.
  \item \textbf{Chapter~\ref{ch:user}} shows that the score depends first on the user being predicted: how often a user changes cell decides most of the result, and the model gains only on the small share of users who move a lot.
  \item \textbf{Chapter~\ref{ch:time}} gives the model the hour of day, checks that it really uses it, and tests whether emphasising two fixed stretches of the day helps; it does on those hours, at a cost everywhere else.
  \item \textbf{Chapter~\ref{ch:groups}} sorts users into four kinds of user according to the hours at which they move, and trains one set of numbers per kind. This is the first configuration that beats the persistence baseline on whole days.
  \item \textbf{Chapter~\ref{ch:scale}} trains on increasing numbers of users, from 400 to 21{,}000, to see whether more data keeps improving the result, explains why the gain stops growing near 2{,}000 users, and tests stretching every day to the same number of records.
  \item \textbf{Chapter~\ref{ch:conclusion}} gathers the findings, the limits of the work, the tasks left undone for lack of time, and the directions worth taking next.
\end{itemize}

Appendix~\ref{app:repro} details experimental hyperparameters and tabular data provenance, while Appendix~\ref{app:glossary} provides a reference glossary of technical domain terminology.
