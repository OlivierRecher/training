\section{Experimental Methodology and Objectives}

Establishing a rigorous modeling and evaluation methodology required resolving two primary technical questions:
\begin{enumerate}
  \item Given constrained computational hardware (a single GPU instance), which model architecture and parameter-efficient fine-tuning method offer feasibility and training efficiency?
  \item What evaluation protocols are necessary to ensure that reported accuracy improvements represent genuine trajectory modeling rather than dataset artifacts?
\end{enumerate}

The selection of model architecture and fine-tuning mechanics remained fixed across experimental iterations, ensuring consistent cross-experiment comparisons. The second question led to three fundamental evaluation principles designed to prevent false positives and over-estimation of baseline performance gains.

\paragraph{Data Provenance.} Empirical measurements presented in this chapter derive from three early dataset cohorts documented in \textbf{Table~\ref{tab:datasets}}: raw logs (\Draw{}), basic filtered logs (\Dfilt{}), and active mobility logs (\Dmob{}). Each cohort evaluates models trained on \textbf{400 subscribers} and graded on \textbf{100 held-out subscribers}. Corresponding persistence baseline accuracies across these three datasets are 69.2\%, 79.0\%, and 45.5\%, respectively.

\section{Parameter-Efficient Fine-Tuning and Model Architecture}
\label{sec:tools-peft}

Fine-tuning pre-trained language models can be conducted under varying memory footprints. Fine-tuning the full parameter set requires substantial memory resources, whereas Parameter-Efficient Fine-Tuning (PEFT) methods freeze pre-trained parameters and train auxiliary low-rank matrices.

\textbf{Figure~\ref{fig:lora}} compares three parameter adaptation mechanisms and their memory cost. Full fine-tuning (\textbf{\panelref{fig:lora}{a}}) modifies 100\% of model parameters, requiring memory to maintain optimizer states for all weights and exceeding the VRAM capacity of standard single-GPU instances. Low-Rank Adaptation, LoRA (\textbf{\panelref{fig:lora}{b}}) \textbf{\cite{hu2022lora}}, freezes the original base weight matrices $W$ and inserts auxiliary low-rank decomposition matrices $A$ and $B$, training only $\approx 2\%$ of total parameters. Quantized Low-Rank Adaptation, QLoRA (\textbf{\panelref{fig:lora}{c}}) \textbf{\cite{dettmers2023qlora}}, further compresses frozen base parameters into 4-bit NormalFloat precision (reducing base memory footprint to $\approx 1/4$) while training 16-bit LoRA adapter weights. QLoRA was selected to enable model execution within 16\,GB GPU memory limits. This selection primarily impacts training throughput rather than model accuracy, accelerating execution from 5.5 hours to 30 minutes per training run and supporting extensive hyperparameter sweeps and per-group adapter routing experiments (Chapter~\ref{ch:groups}).

\subsection{Model Selection and Capacity Evaluation}
\label{sec:tools-model}

Initial experiments evaluated \textbf{Mistral-7B} \textbf{\cite{jiang2023mistral}} (7 billion parameters). A preliminary 30-minute test run on 1.2\% of the dataset yielded 16.87\% top-1 accuracy, verifying pipeline end-to-end functionality. (Comparative tests using Llama models failed to produce syntactically valid cell identifier output.)

However, full training of Mistral-7B required 5.5 hours per run on a single T4 GPU, reaching a maximum accuracy of 41.1\%. In contrast, \textbf{Qwen2.5-0.5B-Instruct} \textbf{\cite{qwen2025}} (500 million parameters, 14$\times$ smaller) completed 49 training epochs in 72 minutes (reducing to 29 minutes under optimized early stopping). Consequently, Qwen2.5-0.5B was chosen for all subsequent experiments.

Because next-cell prediction across 369 discrete vocabulary items requires modeling localized spatial transition patterns rather than general world knowledge or natural language reasoning, the smaller model offers adequate capacity. The $14\times$ parameter reduction provided a $23\times$ speedup per run, enabling extensive experimental iteration within computational constraints.

\section{Data Representation and Tokenization Scheme}

Language models process discrete token sequences. \textbf{Figure~\ref{fig:training-example}} follows one subscriber day from its storage on disk to the sequence handed to the model.

\input{figures/fig-training-example}

On disk (\textbf{\panelref{fig:training-example}{a}}), each day is a JSON Lines record with system, user and assistant role slots, a layout imposed by the \texttt{TRL} library: the first two slots are boilerplate and the trajectory sits in the third. Once tokenized (\textbf{\panelref{fig:training-example}{b}}), the day becomes a sequence built on three encoding choices:
\begin{enumerate}
  \item \textbf{Dedicated Vocabulary Tokens for Cell IDs}: all 369 cell identifiers were added to the model's vocabulary as atomic tokens (dark blue). Subword tokenization can no longer split a string like \cid{BSOCHO1} into pieces, so the model chooses among 369 known answers instead of spelling one out.
  \item \textbf{Explicit Hourly Tokens}: an hour token (\cid{<H00>} through \cid{<H23>}, orange) precedes each cell event. It is an input given for free, never predicted, and costs one token position per event instead of about five for a text string like ``07:31'', which would have cut the visible history by roughly two thirds.
  \item \textbf{Loss Masking}: cross-entropy loss is computed exclusively on cell identifier positions (dark blue); the header boilerplate (grey) and the hour tokens are excluded from the grade.
\end{enumerate}

\subsection{Training Pipeline and Optimization Mechanics}

\textbf{Figure~\ref{fig:training-loop}} details the five-stage training loop:
\begin{enumerate}
  \item \textbf{Sequence Slicing}: sampling sub-sequence windows of timestamped cell events.
  \item \textbf{Target Masking \& Forward Pass}: predicting the next cell token given the preceding context.
  \item \textbf{Surprise Loss Computation}: calculating the cross-entropy loss between the predicted probabilities and the true target cells.
  \item \textbf{Parameter Gradient Updates}: backpropagating gradients to the trainable LoRA adapter weights only ($\approx 2\%$ of parameters), the base parameters remaining frozen.
  \item \textbf{Validation Checkpointing \& Early Stopping}: evaluating accuracy on held-out validation subscribers after each training pass and saving the best checkpoint.
\end{enumerate}
From the sixth experimental iteration onward, two of these steps were modified. At Step~3, \textbf{weighted cross-entropy loss} scales the loss at specific hourly positions by a multiplier (e.g.\ $4\times$ for 18h--20h transitions), emphasizing transition errors without duplicating data. At Step~1, \textbf{targeted sequence sampling} draws training slices containing key transition windows up to $3\times$ more frequently during batch generation.

\section{Evaluation Protocol and Metrics}
\label{sec:scoring}

Model evaluation follows the standardized protocol of \textbf{Figure~\ref{fig:protocol}}.

\input{figures/fig-protocol}

Each test trajectory is split once into a historical prefix handed to the model and a target suffix to be predicted, by default 80\% and 20\% of the day (\textbf{\panelref{fig:protocol}{a}}). Where that cut falls is part of the measurement, not a property of the model (Principle~2 below). The suffix is then evaluated step by step (\textbf{\panelref{fig:protocol}{b}}): the model is asked for the single next cell, graded against ground truth, and given the true event before the next step. It therefore never sees the future and never compounds its own errors, and the persistence baseline is run on exactly the same steps with exactly the same history, which is what makes the two scores comparable.

\textbf{Figure~\ref{fig:topk}} shows how each step is graded. The model does not return a single answer but a probability distribution over all 369 candidate cell tokens, sorted from most to least likely (\textbf{\panelref{fig:topk}{a}}). \textbf{Top-1} accuracy asks whether the true cell ranks first; \textbf{top-3} and \textbf{top-5} whether it appears among the first three or five candidates. In the example drawn, the true cell ranks third, so the same prediction fails at top-1 and succeeds at the other two depths. Reporting these three depths follows the convention of the mobility literature \textbf{\cite{luca2021survey,qin2025mobllm}}. Accuracy itself is a plain count (\textbf{\panelref{fig:topk}{b}}): correct steps divided by evaluated steps across the held-out test subscribers, ten steps with seven correct giving 70\%. The persistence baseline is counted on the same steps, and every result in this report is the difference between the two counts.

\section{Evaluation Methodology Principles}

\subsection{Principle 1: Early Stopping and Overfitting Mitigation}

This principle corresponds to \textbf{Figure~\ref{fig:rule-peak}}. Fine-tuning language models on small trajectory datasets leads to severe overfitting when trained for too many epochs. \textbf{Figure~\ref{fig:validation-curves}} shows four training runs on four datasets: the horizontal axis counts training passes, the vertical axis is accuracy on unseen held-out subscribers, the solid line is the model with a star at its best pass, and the dashed line is the persistence baseline on the same subscribers. In all four panels, validation accuracy peaks within 4 to 9 passes and then declines, while training loss keeps decreasing: the model has moved from learning how the population moves to memorizing its training examples.

\input{figures/fig-rule-peak}

\input{figures/fig-validation-curves}

In the extended 49-epoch run of \textbf{\panelref{fig:validation-curves}{a}}, validation accuracy peaked at epoch 9 (65.0\% validation, 64.2\% test) before degrading to 48.1\% (48.7\% test) at epoch 49. Reading the final epoch instead of the peak would cost \textbf{15.5\,\%} of test accuracy on held-out subscribers. Early stopping at peak validation accuracy, alongside regularization (dropout 0.1, weight decay, learning rate scheduling), preserved generalization and reduced training time from 72 to 29 minutes. The dashed baseline moves from panel to panel (69.2\% on the unfiltered day of \textbf{\panelref{fig:validation-curves}{a}}, 43.5\% once only mobile subscribers are kept) because the subscribers differ, so the panels are comparable only on the gap between solid and dashed line; in all four, that gap is negative. All subsequently reported metrics evaluate the checkpoint saved at peak validation accuracy.

\subsection{Principle 2: Context Fraction and Evaluation Split Sensitivity}

This principle corresponds to \textbf{Figure~\ref{fig:rule-cut}}. The prefix context fraction (share of the trajectory provided to the model before prediction) directly affects task difficulty and baseline performance. \textbf{Table~\ref{tab:context-sweep}} presents model performance across context fractions from 30\% to 90\% on \Dfilt{} and \Dmob{}: \textbf{Rule} is the persistence baseline on the same steps, and \textbf{Distance}, model minus baseline, is the only column that compares like with like. Moving the cut alters the baseline score itself, because it shifts which event counts as ``the most recent cell.'' On \Dfilt{}, evaluating at an 80\% context fraction yields 80.1\% model accuracy against a 79.0\% persistence baseline (+1.1\%), whereas evaluating at a 70\% context fraction trails the baseline by 0.3\%. On \Dmob{}, absolute model accuracy increases from 41.5\% to 47.6\% as the context fraction expands from 30\% to 90\%; however, baseline accuracy increases at an identical rate (42.9\% to 50.9\%), leaving the performance delta negative across all cuts (these \Dmob{} rows are one model read at seven cuts, hence their identical \textbf{Valid.} column, whereas each \Dfilt{} row is a separate run). Consequently, apparent accuracy gains resulting strictly from expanding historical context represent measurement ruler artifacts rather than model improvements, requiring context fractions to be held constant during comparative evaluations.

\subsection{Principle 3: Baseline Upper Bounds and Task Room Constraints}

This principle corresponds to \textbf{Figure~\ref{fig:rule-room}}. On unfiltered daily logs, the persistence baseline achieves 69.2\% accuracy due to high stationary periods. A model achieving 64.4\% accuracy on such raw data has not failed in learning mobility patterns; rather, it has been evaluated on a benchmark dominated by stationary trivial predictions. Restricting benchmarks to active mobile trajectories (reducing baseline score to 45.5\%) creates a viable dynamic evaluation range.

\subsection{Methodological Implications for Hyperparameter Optimization}

Applying these three evaluation principles summarized in \textbf{Figures~\ref{fig:rule-peak}, \ref{fig:rule-cut} and~\ref{fig:rule-room}} revealed that hyperparameter tuning alone yields limited performance improvements on uniform cohorts. Individual predictions revealed stark disparities: stationary trajectories were predicted with near 100\% confidence, whereas active transition trajectories resulted in incorrect baseline-like predictions. This variance across individual subscriber profiles motivated the individual user analysis presented in Chapter~\ref{ch:user}.

\section{Conclusion}
\label{sec:retro-tools}

This chapter established a standardized model fine-tuning architecture (Qwen2.5-0.5B fine-tuned via QLoRA with explicit cell and hour tokenization) and a rigorous evaluation protocol. Model capacity and PEFT mechanics remained fixed, allowing subsequent experimental gains to be attributed strictly to data representation and user conditioning mechanisms.

Establishing early stopping (\textbf{Figure~\ref{fig:validation-curves}}), standardized context fraction splits (\textbf{Table~\ref{tab:context-sweep}}), and active mobility cohort benchmarking eliminated false positive findings and provided a reliable foundation for subsequent research chapters.

In hindsight, these three principles weigh more than any setting tuned in this chapter. Reading the best saved copy instead of the last pass is worth 15.5 correct answers per hundred on its own (\textbf{Figure~\ref{fig:rule-peak}}), far more than any later gain of the project (at most +4.3\,\%). Moving the cut of the day raised the model from 41.5\% to 47.6\% while the baseline rose from 42.9\% to 50.9\% (\textbf{Table~\ref{tab:context-sweep}}), so a rising score was never evidence on its own. Measuring on people who move nearly doubled the room left to a model, from 30.8 to 54.5 correct answers per hundred (\textbf{Figure~\ref{fig:rule-room}}). Every result in the following chapters is read under these three rules.
